# Setu Evaluation

Setu is evaluated on a reproducible synthetic corpus rather than real financial documents. The goal
is to test correctness and safe failure within a known scenario, not to claim general accuracy across
all institutions and PDF layouts.

The recorded live-model result is in
[`evaluation/final-evaluation.json`](evaluation/final-evaluation.json).

## Evaluation questions

The final evaluation asks:

1. Does Setu route each supported synthetic document to the correct processing path?
2. Do extracted holdings reconcile with independently specified statement totals?
3. Does a planted mismatch pause for review instead of reaching persistence?
4. Does exact USD/INR aggregation reproduce the independently generated ground truth?
5. Is ROI shown only when a document provides cost basis?
6. Is term-insurance coverage excluded from current wealth?
7. Are current, short-term, and long-term risks produced from explainable deterministic evidence?
8. Is raw document access absent from Claude's tool registry?
9. Can the configured live local model recover every synthetic holding and its cost basis?

## What the tests cover

The 110-test regression suite includes:

- Exact FX and net-worth calculations.
- Temporal latest-snapshot selection and idempotency.
- Holdings cost-basis evidence and missing-cost behavior.
- Bank balance extraction and reconciliation.
- LIC, endowment, ULIP, and term-policy parsing and valuation safety.
- Maturity-outlook evidence rules.
- LangGraph interruption, resume, and reject behavior.
- Dashboard authentication, upload limits, review endpoints, and safe error responses.
- Reversible statement activation and linked-record exclusion.
- Claude credential isolation, tool-loop bounds, and sanitized tool schemas.
- Isolated demo-database setup and expected health-score components.

## Reproduce the result

Offline deterministic evaluation:

```bash
uv run setu evaluate
uv run pytest -q
```

Include the live Ollama extraction check:

```bash
ollama serve
ollama pull qwen2.5:7b
uv run setu evaluate --live-model
```

## Limitations

- Six documents and seven investment holdings are too small to estimate general document accuracy.
- The corpus is generated by Setu, so it does not represent every layout defect found in real PDFs.
- The live-model metric checks exact fields in three investment statements; policy safety is tested
  more extensively through deterministic and model-failure regression cases.
- OCR logic is covered by tests, but this final recorded run used generated text PDFs rather than a
  scanned-image benchmark.
- Passing safety tests demonstrates the implemented boundaries, not regulatory compliance or
  investment suitability.

These limits are part of the result. The evaluation establishes a repeatable capstone baseline and a
framework for adding anonymized documents later without changing the metrics.
